# 0.5.0 release guide

Target: `@jaminzhou/codex-app-server-client@0.5.0`, non-preview, intended npm tag `latest`.
This source record alone does not prove the version has been published; check the npm registry for
the exact version and tag state.

```bash

npm install --save-exact --ignore-scripts --include=optional @jaminzhou/codex-app-server-client@0.5.0

```

## Scope and migration

This release target updates the bundled Codex runtime and generated public app-server protocol from
`0.158.0` to `0.159.0` (`rust-v0.159.0`, public source commit
`687a119f0fcaace47e1f1abcc77cec6c813fd6da`). It adds the `tooManyDenials` error variant, optional
`mcpServerStatus/list.serverName` filtering, and a structured item anchor for `thread/items/list`
pagination. Existing string cursors and public methods remain available; no public method or
generated type is removed.

`ThreadItemsListCursor` now accepts either the continuation string returned by the server or an
exclusive `{ type: "item", itemId }` anchor scoped to a non-empty `turnId`. Ascending (the default)
returns items after the anchor; descending returns items before it. Continue a page sequence with the
opaque string cursor returned by the server.

The `Turn.error` description now includes failed and interrupted turns. This clarifies the existing
field; its wire shape is unchanged. The new MCP filter is an optional request field and does not
change which servers a normal unfiltered list returns.

This remains a pre-1.0 API. Pin the exact package version, retain the lockfile, and run your normal
initialization, approval, interruption/resume, and pagination tests before upgrading. See
[compatibility guidance](../../COMPATIBILITY.md) and the [API reference](../api.md).
If upgrading from before client `0.3.0`, also review its removal of the upstream-retired
`thread/rollback` request and response types in the [0.3.0 migration guide](./0.3.0.md).

## Verification boundaries

Candidate preparation, reviewed merge, OIDC publication, registry read-back, and exact npm/pnpm
consumer checks are separate release stages. Follow the current gates in
[`RELEASING.md`](../../RELEASING.md); neither this guide nor a source version proves publication.
Compatibility and example smoke tests use isolated app-server processes and local fixtures. They do
not establish real-account OAuth, live-account access, or model-quality acceptance.
