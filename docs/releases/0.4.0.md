# 0.4.0 release guide

Target: `@jaminzhou/codex-app-server-client@0.4.0`, non-preview, intended npm tag `latest`.
This source record alone does not prove the version has been published; the npm registry is
authoritative for exact-version availability.

```bash
npm view @jaminzhou/codex-app-server-client@0.4.0 version --registry https://registry.npmjs.org/
npm install --save-exact --ignore-scripts --include=optional @jaminzhou/codex-app-server-client@0.4.0
node node_modules/@jaminzhou/codex-app-server-client/examples/stream.mjs
```

## Scope and migration

This release target updates the bundled Codex runtime and generated public app-server protocol from
`0.157.1` to `0.158.0` (`rust-v0.158.0`, public source commit
`064c6b8c737f5b41d171fdda80bd9ef10ad06eb3`). It adds the `promax` plan, the `flexUnavailable`
error, and optional `EnvironmentAddParams.authBearerToken` for executor authentication.

Upstream removed its plugin-extension types and `PluginSummary.extensions`. Accordingly, this
release removes the generated public TypeScript exports `PluginEntrypoint`, `PluginExtensions`,
`PluginIcon`, `PluginQuickAction`, `PluginQuickActionTarget`, `PluginSearchProvider`,
`PluginSearchProviderCall`, `PluginSettings`, and the `PluginSummary.extensions` property. This is a
breaking TypeScript API change; consumers importing these types or depending on that property must
remove or adapt those references. No client method was removed in this release.

If upgrading from before client `0.3.0`, also review its removal of the upstream-retired
`thread/rollback` method and the migration guidance in the [0.3.0 release guide](./0.3.0.md).

The client remains pre-1.0. Pin an exact version, retain the lockfile, and run your normal
initialization, approval, interruption/resume, and migration tests before upgrading. See
[compatibility guidance](../../COMPATIBILITY.md) and the [API reference](../api.md).

## Verification boundaries

Candidate preparation, reviewed merge, OIDC publication, registry read-back, and exact npm/pnpm
consumer checks are separate release stages. Follow the current gates in
[`RELEASING.md`](../../RELEASING.md); neither this guide nor a source version proves publication.
Compatibility and example smoke tests use isolated app-server processes and local fixtures. They do
not establish real-account OAuth, live-account access, or model-quality acceptance.
