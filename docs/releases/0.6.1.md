# 0.6.1 source-candidate record

Candidate version: `@jaminzhou/codex-app-server-client@0.6.1`. This is an unpublished source
candidate. Check the npm registry before preparing an exact release archive; source metadata
alone does not establish publication or select candidate bytes.

## Scope and migration

Update the bundled runtime from `@openai/codex@0.162.0` to `0.162.1`, using public tag
`rust-v0.162.1` at commit `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`.
The generated public protocol and method maps are unchanged. There are no public method, type,
or Schema additions or removals, and no new high-level client behavior.

The upstream patch fixes multiline asynchronous-question rendering and limits shared-daemon
feature compatibility checks to explicit CLI overrides. Those upstream release notes do not
imply that this client's local stdio workflows previously reproduced either TUI issue.
See the [upstream release](https://github.com/openai/codex/releases/tag/rust-v0.162.1).

The compatibility matrix retains `0.162.0` and adds `0.162.1`. The immutable published client
`0.6.0` continues to bundle `0.162.0`; installing a newer global CLI does not change that archive.
Consumers upgrading from before client `0.3.0` must still review the historical `thread/rollback`
removal in the [migration record](./0.3.0.md).

## Verification boundaries

Local verification on macOS arm64 with Node 22.22.2:

- Protocol regeneration changed only version/provenance metadata; generated types, Schemas,
  173 client-method mappings and 11 server-request mappings remain unchanged.
- `pnpm check` passed all 21 test files and 197 tests, TypeScript checks and build.
- `pnpm protocol:latest-check` verified npm's latest stable version and the exact public tag commit.
- `pnpm compatibility:smoke` passed all 16 isolated runtimes from `0.150.1` through `0.162.1`.
- The clean npm installed consumer passed strict declarations, ESM/schema exports, the real bundled
  binary, all 19 shipped examples and 4 CLI input cases, including cleanup.

Before selecting a release archive, verify protocol generation/check and public-tag provenance,
the full compatibility matrix, TypeScript checks, deterministic real-runtime tests, and npm/pnpm
installed consumers. PR CI must exercise the package on Linux, macOS and Windows. The OIDC
candidate must come from reviewed, clean current `main` and preserve its exact bytes and identity.

These checks do not establish real-account OAuth, model quality, every operating-system/architecture
pairing, or successful publication. Publication requires the separate unchanged OIDC gates and
registry read-back described in [RELEASING.md](../../RELEASING.md).
