# 0.3.0 release guide

Target: `@jaminzhou/codex-app-server-client@0.3.0`, non-preview, intended npm tag `latest`.
The npm registry is authoritative for availability; this source record alone does not prove the
version has been published.

```bash
npm view @jaminzhou/codex-app-server-client@0.3.0 version --registry https://registry.npmjs.org/
npm install --save-exact --ignore-scripts --include=optional @jaminzhou/codex-app-server-client@0.3.0
node node_modules/@jaminzhou/codex-app-server-client/examples/stream.mjs
```

## Scope and migration

This release target updates the bundled Codex runtime and generated public app-server protocol from
`0.155.1` to `0.156.1`, including new request and schema shapes while preserving fields that remain
optional on supported older app-server versions. The public method type removes upstream-retired
`thread/rollback`. This is a source-level breaking change for callers that invoke the method through
the typed client or import its generated request/response types. `thread/revert` remains in the
protocol, but its semantics are not interchangeable by assumption; migrate only after checking the
upstream contract and the behavior your application needs.

The release also extends the bounded, read-only npm registry visibility checks used by the
repository's OIDC publication workflow. Publication remains non-retriable and identity or integrity
mismatches fail closed; these are release-tooling changes, not runtime SDK features.

The client remains pre-1.0. Pin an exact version, retain the lockfile, and run your normal
initialization, approval, interruption/resume and migration tests before upgrading a production
application. See [compatibility guidance](../../COMPATIBILITY.md) and the
[API reference](../api.md).

## Verification boundaries

Candidate preparation, reviewed merge, OIDC publication, registry read-back and installed npm/pnpm
consumer checks are separate release stages. Follow the current gates in
[`RELEASING.md`](../../RELEASING.md); neither this guide nor a source version proves publication.
Local-provider and scripted-RPC tests do not establish real-account OAuth, biometric, or
model-quality acceptance.
