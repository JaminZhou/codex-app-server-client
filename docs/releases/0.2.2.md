# 0.2.2 release guide

Target: `@jaminzhou/codex-app-server-client@0.2.2`, non-preview, intended npm tag `latest`.
This document describes the candidate and its release gates; the registry is the authority for
publication status.

```bash
npm view @jaminzhou/codex-app-server-client@0.2.2 version --registry https://registry.npmjs.org/
npm install --save-exact --ignore-scripts --include=optional @jaminzhou/codex-app-server-client@0.2.2
node node_modules/@jaminzhou/codex-app-server-client/examples/stream.mjs
```

## Scope and migration

This release upgrades the bundled Codex runtime and generated app-server protocol from `0.154.0`
to `0.155.1`. It adds typed `userVerification/cancel`, `memory/status`, thread attachment
add/list/remove methods, the attachment-updated notification, and the optional feedback prompt
hash. It also carries the official-example alignment and the reliability fixes documented in the
changelog. The client remains a pre-1.0 API; consumers should pin the exact version and retain
their lockfile.

The published `0.2.1` archive remains immutable on the `0.154.0` baseline. Consumers moving from
`0.2.1` should run their normal initialization, approval, interruption/resume, and attachment
flows against this version before upgrading a production lockfile. The generated experimental
surface remains version-sensitive; read [compatibility guidance](../../COMPATIBILITY.md).

## Release gates

1. Review the version/docs changes, run `pnpm check` and current-head cross-platform CI,
   including Git and installed-package checks. Obtain fresh post-push bot review, resolve
   actionable bot findings, merge only with authorization and verify post-merge main CI.
2. Prepare a clean immutable candidate with `npm-release-candidate.yml` for `0.2.2`. Require
   compatibility, upstream drift, and exact npm/pnpm archive consumer checks. Retain the
   successful run's archive and evidence separately from historical approved artifacts.
3. Approve the exact version, source SHA, candidate run ID, SHA-512 integrity and intended
   `latest` tag. Do not rebuild approved bytes.
4. Acceptance is deterministic real-runtime/local-provider and scripted RPC testing: the full
   official-example suite and CLI input cases. It does not establish fresh real-account, OAuth,
   biometric or model-quality acceptance.
5. Publish only the approved retained archive through the configured main-restricted OIDC
   workflow. Verify all registry tags, dependencies and downloaded-byte integrity, then fresh
   exact-version npm/pnpm registry consumers. Retain the complete publication receipt.

Detailed commands and recovery boundaries are in [RELEASING.md](../../RELEASING.md).
